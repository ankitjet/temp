To create version 1.0.2 of the image img-appbase-rhel810-hardened-v1 with the certificate issue resolved, follow these complete steps. This is the standard process for updating an Azure Compute Gallery (SIG) image.1ca0dc
Recommended Approach (Safest)
Create a temporary VM from the working version 1.0.1.
Apply the certificate fix on that VM.
Generalize + Capture the VM as version 1.0.2.
Step-by-Step Instructions
1. Create a Test VM from Version 1.0.1
Azure Portal:
Go to Virtual machines → + Create.
In Image, browse to your gallery → select img-appbase-rhel810-hardened-v1 → choose Version 1.0.1.
Configure VM (size, networking, SSH key, etc.).
Create the VM.
Azure CLI (preferred for precision):
az vm create \
  --resource-group <Your-RG> \
  --name FixCertTestVM \
  --image "/subscriptions/<sub-id>/resourceGroups/<gallery-rg>/providers/Microsoft.Compute/galleries/<gallery-name>/images/img-appbase-rhel810-hardened-v1/versions/1.0.1" \
  --admin-username azureuser \
  --generate-ssh-keys \
  --size Standard_D2s_v5 \
  --location eastus
2. Fix the Certificate Issue on the VM
SSH into the new VM and apply the certificate fix (e.g., update CA trust store, install missing certs, configure OpenSSL, or whatever resolved it in 1.0.1).
Example common commands for RHEL 8.10:
sudo dnf update ca-certificates
sudo update-ca-trust
# Or install specific certs, update openssl, etc.
# Test your application or `curl` / `openssl s_client` to verify
Make sure the fix is permanent (installed in the right system paths).
3. Generalize the VM (Critical for Reusability)
Inside the VM (via SSH):
sudo waagent -deprovision+user -force
Type y if prompted.
Exit the SSH session.
From your local machine / Azure CLI:
# Deallocate
az vm deallocate --resource-group <Your-RG> --name FixCertTestVM

# Generalize
az vm generalize --resource-group <Your-RG> --name FixCertTestVM
4. Create New Image Version 1.0.2
Azure Portal:
Go to the VM → Click Capture in the top menu.
Choose Azure Compute Gallery.
Select your existing Image definition (img-appbase-rhel810-hardened-v1).
Set Version number to 1.0.2.
Add a description (e.g., "Certificate fix applied").
Choose Target regions and replication count.
Click Review + create → Create.
Azure CLI (more control):
az sig image-version create \
  --resource-group <gallery-resource-group> \
  --gallery-name <your-gallery-name> \
  --gallery-image-definition img-appbase-rhel810-hardened-v1 \
  --gallery-image-version 1.0.2 \
  --virtual-machine "/subscriptions/<sub-id>/resourceGroups/<Your-RG>/providers/Microsoft.Compute/virtualMachines/FixCertTestVM" \
  --target-regions eastus=1 centralus=1 \
  --replica-count 2 \
  --storage-account-type Standard_LRS
This process can take 15–60+ minutes depending on replication.
5. Verify the New Version
az sig image-version list \
  --resource-group <gallery-rg> \
  --gallery-name <gallery-name> \
  --gallery-image-definition img-appbase-rhel810-hardened-v1 -o table
Check status in the portal under the image definition → Versions.
Important Notes
Generalized vs Specialized: Use generalized (as above) unless you want machine-specific accounts preserved.
Permissions: You need Contributor/Owner rights on the gallery.
Cleanup: After successful capture, delete the temporary FixCertTestVM to save costs.
Best Practice: Consider using Azure Image Builder for future versions — it’s more automated and repeatable.534c58
Replication: Ensure the new version replicates to the regions you need.
